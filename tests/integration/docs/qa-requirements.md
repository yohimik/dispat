# Release-candidate requirement matrix

This is the acceptance inventory for the release candidate. Its denominator is the behavior dispat implements: the
command tree and flags under `services/dispat/internal/cli`, the configuration model in
[`pkg/models`](../../../pkg/models/models.go) as the [configuration reference](../../../packages/docs/docs/configuration/README.md)
describes it, the current documentation under `packages/docs/docs`, and the parts of the
[CCME specification](../../../specs/ccme-spec/SPEC.md) dispat implements. It is not an inventory of test-plan headings: the
[test plan](./test-plan.md) says what each test proves, and this matrix says which released behavior that is evidence
for.

Every row states one requirement as a primary goal and one explicit behavioral assertion, and names the assertions that
demonstrate it. A reference is a globally unique `TestName` or a `path/to/file_test.go::TestName` qualified by the file
that declares it.

**Status is derived, not declared.** `go run ./tools/testreport testplan .` reads this file, resolves every reference
against the tree, and refuses a row whose status is not the one its references support:

- **mapped** means at least one named assertion exists.
- **uncovered** means no adequate assertion exists yet.

Whether a mapped assertion *passed* is the suite run's answer, recorded with its revision in the release evidence, not
something this file may claim on its own. A documented test is not evidence that it ran.

**Critical** marks a release-safety requirement: the ones where a defect publishes something wrong, republishes
something already out, loses the record of a publication that cannot be undone, or acts on a repository the operator
excluded. Locks, partial publication, records, cancellation, drift, duplicate publication, credential redaction and
repository exclusion are all in this set.

## Gates on this matrix

The traceability gate is `go run ./tools/testreport testplan .`, wired into CI as the `repo-checks` target of
`Dockerfile.gotest` and runnable locally through `scripts/check-test-plan.sh`. It fails on a reference to a test that
does not exist, on an ambiguous bare name that more than one validated module declares, on an integration test with no
goal in the [test plan](./test-plan.md), on a row whose status its references do not support, and on a mapped or
critical percentage below the thresholds the gate is given. `scripts/check-test-plan-test.sh` runs the gate's own
tests, which are Go tests of the command in `tools/testreport/testplan_test.go`.

Reference integrity is not the same claim as coverage. A named assertion is evidence only once the suite that contains
it has run: `testreport coverage -minimum-integration 95 -minimum-total 95` is the separate gate over the profiles, and
it rejects missing, stale, mixed-commit, unexpected and orphan evidence before reporting a number.

The environmental limits stand. Disposable local Git repositories and deterministic HTTP fixtures do not exhaust every
hosting provider failure, filesystem, credential helper or network partition. The release experiments supplement those
fixtures with selected partial-publication protocols, and a recorded failure there stays a failure rather than being
rewritten as a successful observation.
