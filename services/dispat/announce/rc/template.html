NOTES

Monorepo: release packages that live in one repository.

Orchestration: start from one chosen repository to coordinate releases across linked repositories.

Choreography: start a release from any linked repository.

Both approaches to linked repositories work without a separate control repository. Each repository keeps its own configuration and release history.

Connect repositories with a star, a minimal tree, or your own tree of links. `dispat compute --topology star` proposes direct links from the current repository to every other one. `dispat compute --topology minimal` keeps existing links and adds only what is needed. Custom links must connect the repositories without loops.

Both commands preview changes. Add `--write` to apply them. Existing links are kept.

Before planning, dispat locks every participating repository. If any lock fails, the release stops. It then calculates versions and releases dependencies before the packages that need them.

If a library releases but an app using it fails, the successful release stays recorded. The next run plans the unfinished work without releasing the library again. This is saga recovery: keep what succeeded and finish what remains.

Autistic stability for ADHD projects. Mathematical planning. Saga recovery.

Check the plan with `dispat status`. It publishes nothing and takes no release locks.
