# npm publication completed without release records

- **Date:** 2026-09-11
- **Affected package:** `@dispat/cli@1.10.0`
- **Workflow run:** `34584443988`
- **Source revision:** `c58722dd`
- **Status:** Package removed; forward recovery prepared for `1.10.1`

## Summary

The release workflow uploaded `@dispat/cli@1.10.0` to npm, then the package's
publish script performed a registry lookup. npm had exited successfully, but the
lookup returned no version at that moment. The script converted the completed
upload into a publish failure. dispat therefore did not create or push the
package release tag and records.

The uploaded tarball had the expected integrity:

```text
sha512-v0LSO7aoBL60toA8g905JkrIhQRUVGqWBZfM54MZRX7NrLBbV9dQaNLmcTZj64h2ZVQUJT40jPE8Jg9YR2M7bA==
```

The incident was a release-recording anomaly. No evidence showed that npm
accepted different bytes. The post-upload lookup created the failure boundary:
an external publication had completed, but dispat was told publication failed
before it could write the durable Git records.

## Timeline

- Release run `34584443988` started from `c58722dd` with the built and smoke-tested
  `@dispat/cli@1.10.0` tarball.
- `npm publish` exited successfully and npm accepted the package.
- The publish script performed a post-upload registry integrity lookup. That
  lookup returned the version as missing.
- The publish script failed reconciliation. The workflow stopped without a
  remote `packages/cli/v1.10.0` tag.
- Read-only inspection later found `@dispat/cli@1.10.0` publicly available with
  the expected integrity, confirming that publication and recording had split.
- The decision was made to remove the package completely.
- The authenticated unpublish was completed. At 2026-09-11 09:57 UTC,
  independent public checks returned 404 for both the package metadata and the
  original tarball.

## Impact

- `@dispat/cli@1.10.0` existed without its matching remote dispat release tag.
- Consumers could observe a package version the repository did not record as
  released.
- npm permanently reserves a published name and version, including after
  unpublish. Version `1.10.0` cannot be reused.
- Complete package removal starts npm's 24-hour waiting period before another
  version can be published. Using the verification time, 2026-09-12 09:57 UTC
  is the conservative earliest time for a replacement release; the exact
  deletion time was not independently recorded.

## Correction

The package now validates everything before publication:

- release metadata identifies the exact native `1.10.0` provider assets;
- the build creates one tarball and records its path, name, version, and digest;
- pre-publication validation compares the tarball identity with the reconciled
  npm manifest and streams the file through SHA-512;
- the artifact smoke test installs and executes that same tarball;
- release outputs must continue to identify that same artifact.

The publish script then performs one command:

```text
npm publish <tarball> --access public --provenance --tag <channel>
```

That command is the final step in the publish stage. A successful npm exit
returns success immediately to dispat so it can create the native release
records. The publisher performs no post-upload registry lookup, version or
integrity comparison, status gate, retry reconciliation, or dist-tag mutation.
npm output remains visible and a nonzero npm exit still fails the package leg.

Recovery advances the npm distribution to `1.10.1`; it does not recreate
`1.10.0`. The native provider remains `1.10.0` because its bytes did not change.
The npm manifest version is not hand-edited: the final reviewed CCME release
record supplies `1.10.1` through the normal CI workflow.

## Prevention and verification

The regressions cover:

- the exact single npm command and the absence of publisher registry operations;
- stable and prerelease channel arguments;
- propagation of npm failures to a nonzero entrypoint exit;
- a real npm upload to a disposable localhost registry;
- successful publisher exit when npm accepts the upload while later registry
  metadata is unavailable;
- incomplete artifact records, name/version conflicts, release-output conflicts,
  and tarball mutation after packing;
- streaming digest verification before publication.

The final package suite passed 54 tests on the host and in the package's Docker
gate with 99.82% executable line coverage and 96.59% branch coverage. Release
scripts reached 100% line and 99.04% branch coverage. Current and version 1.10
recovery documentation passed the documentation tests and production build.

The agent guide now requires all checks before publication, the publication
command as the final external action in the publish stage, and immediate success
return for native recording. It also requires operator-confirmed release intent
and full-plan review before release.

No production publish, Git tag, dist-tag mutation, or push was performed while
preparing this correction.
