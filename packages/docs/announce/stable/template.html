NOTES

Start a release on one machine and let others do the building. The machine you started on keeps the locks, the plan and the records.

Everything travels over Git. The orchestrator leaves work on branches of the project's own repository and workers pick it up, so there are no open ports and nothing to install but dispat.

What one machine builds, the next one can use, checked before it is used.

Publishing and credentials stay on one machine. Without a workers section, nothing changes.

New and optional: a sign stage writes each package's own version before anything else runs, and the version stage can be written as propagate. Existing configurations run exactly as before.

Faster on long histories: planning a 50,000-commit benchmark takes 0.4 seconds instead of 2.9.

If a library ships and an app using it fails, nothing is repeated: the next run finishes what is left. An app with changes of its own ships anyway and picks the library up later, also when it sat out the run where the library shipped.

Autistic stability for ADHD projects. Mathematical planning. Saga recovery.

Preview with `dispat status`; it publishes nothing.
